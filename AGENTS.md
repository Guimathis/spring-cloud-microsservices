# Bookstore API

Teaching project for a Spring Boot course. A simple, complete CRUD for books,
with an AI-generated summary on creation.

## Stack
- Java 25, Spring Boot 4.1, Maven
- PostgreSQL on Neon. Schema generated by Hibernate `ddl-auto: update`.
  No migration tool.
- Spring AI 2.0 for the summary generation
- All code and identifiers in English

## Commands
- Run: `mvn spring-boot:run`
- Build: `mvn -q verify`

## Naming
- Tables: `tb_<plural_name>` — e.g. `tb_books`
- Entities: `<Name>Model` — e.g. `Book`
- Input DTOs: `<Name>RecordDto` as Java records — e.g. `BookRecordDto`
- There are NO output DTOs. Controllers return the entity directly.

## Hard rules
- NO Lombok. Write constructors, getters and setters by hand.
- Use `BeanUtils.copyProperties` to copy from the record DTO to the entity.
- Business logic lives in the service layer. Controllers only translate
  HTTP to service calls and back.
- Do not include logging unless explicitly requested.
- Never change `ddl-auto` away from `update`.
- Use UUID-type identifiers.
- Dont need to write all the changes that you make in a file on the chat.
- Never execute `git commit` or `git push` autonomously.

## Guardrails
Enforced across all agents and tooling (via `scripts/guardrails.sh` and build checks).
- Prohibited autonomous commands: `git commit`, `git push` (never run autonomously).
On `.java` files, the following patterns are strictly forbidden:
- `import lombok` (no Lombok allowed)
- `@Autowired` on its own line (field injection — always use constructor injection)

If a rule is violated, fix the code immediately — do not attempt to bypass the rules.

## Teaching mode
This code will be explained line by line on video.
- Generate ONE file at a time unless asked otherwise.
- Prefer clear and explicit over clever or compact.
- Do not add comments explaining what the code does — that is narrated.
- Do not add features that were not asked for.
